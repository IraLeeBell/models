# Writing digests

Each model folder has an original digest of the publisher's document. It is this repository's own writing (MIT license), not an extract. The digest serves two audiences:

- **People choosing a model.** Enablement leads, platform teams, and developers skim the top of `digest.md` for 60–90 seconds to learn what the model is, what it is good and bad at, what its safety posture means for agentic coding, and when to pick it in Copilot.
- **Programs.** Scripts, model routers, dashboards, retrieval pipelines, and LLM-as-judge prompts load `digest.json` (joined with `catalog.json` by slug) or the aggregate [`digests.json`](digests.json). They rely on stable keys, typed values with units, controlled identifiers, explicit `null` for anything the document does not state, and a citation on every fact.

So **`digest.json` (schema_version 2) is the only authored file.** `digest_check.py --write` normalizes it and renders `digest.md` from it and `catalog.json`; the checker rejects a `digest.md` that differs from the rendering. Every fact a reader sees therefore exists as data, and the same input always produces the same output.

| File | Role |
| --- | --- |
| `<slug>/digest.json` | Authored digest. Validates against [`digest.schema.json`](digest.schema.json). |
| `<slug>/digest.md` | Rendered for reading. Never edit by hand. |
| [`vocabulary.json`](vocabulary.json) | Controlled identifiers: benchmarks, metrics, units, modalities, tools, use cases, safety frameworks, determinations, risk topics, and card types. |
| [`digest.schema.json`](digest.schema.json) | JSON Schema (draft 2020-12) generated from `digest_check.py` and the vocabulary. |
| [`digests.json`](digests.json) | Every digest joined with its catalog entry. Generated by `generate.py`. |
| [`BENCHMARKS.md`](BENCHMARKS.md) | Results for benchmarks that two or more digests report. Generated by `generate.py`. |

## Workflow

1. Create the local extraction: `python3 local_cards.py --model <slug>` writes `system-card.md`, plus `supplements/<document-id>.md` when the model has supplements. Each PDF page begins with `<!-- page N of M -->`. Cite these PDF page numbers N, not the numbers printed in the document's footers. A ````text block on a page holds that page's complete plain text. Figures and text inside images are not transcribed: to read a chart, render the page (`fitz.open(pdf)[N - 1].get_pixmap(dpi=110).save("page.png")` with PyMuPDF from `requirements-local.txt`) and look at it.
2. Read the model's `catalog.json` entry (`scope`, `scope_terms`, `card_note`, `note`, `lifecycle`, `supplements`) and its document's entry.
3. Read the document broadly: contents, model description, capabilities and benchmarks, the safety framework determination, dangerous-capability evaluations, alignment and agentic-safety sections, then limitations. Verify every number against the page you cite.
4. Edit `digest.json`, then run `python3 digest_check.py --write <slug>` until it prints `digests OK`.
5. Run `python3 generate.py --write` to refresh `digests.json`, `BENCHMARKS.md`, and the other generated files, then `python3 generate.py --check`.

## `digest.json` fields

Write keys in any order; `--write` rewrites the file in canonical order with defaults filled. Fields marked *derived* come from `catalog.json` and are overwritten by `--write`, so you may omit them.

### Identity and sources

| Key | Type | Notes |
| --- | --- | --- |
| `schema_version` | `2` | Required. |
| `slug`, `model`, `publisher`, `lifecycle`, `retired_on` | derived | Must match the catalog. |
| `document` | object or `null` | `{"id": "<catalog document id>"}`; title, publisher, date, format, and pages are derived. `null` when the catalog maps no document. |
| `supplements` | list | One entry per catalog supplement: `{"id": "...", "label": "August update"}`. Only `label` is authored; it prefixes citations. |
| `sources` | list | `{"title": "...", "url": "https://..."}` for owner documentation cited with `source` (no-card folders, or a publisher page that documents a serving mode). |
| `coverage` | object | `card_type` from the vocabulary (`dedicated`, `family`, `appendix`, `same-weights`, `none`); `document_model_names`: the exact names the document uses for this model; `model_pages`: pages specific to this model (empty when the whole document is about it); `note`: 80–900 characters on which parts apply to this model, which to siblings, and what the digest omits. |

### Reader summary

| Key | Type | Notes |
| --- | --- | --- |
| `summary` | string, 80–600 characters | Two to four sentences: what the model is, who published it, how it differs from its predecessor or siblings, and the one or two things that matter most for model choice. |
| `at_a_glance.choose_it_for` | string, 20–240 characters | One line on the work this model suits best. |
| `at_a_glance.watch_out_for` | string, 20–240 characters | One line on the most decision-relevant risk or gap. |
| `at_a_glance.points` | 3–6 cited text items | Decision-first: coding and agentic standing with numbers, the headline safety determination, modalities and limits, and the agentic-risk picture. No filler. |

### Facts

`facts` has all 13 keys below, always. Each is `{"value": ..., "as_stated": ..., "note": ..., "pages": [...], "document": ...}`. Use `"value": null` when the document does not state the fact; a non-null value needs a citation. `as_stated` (up to 120 characters) records the document's wording when you normalized it; `note` (up to 300 characters) records qualifications.

| Key | Value type |
| --- | --- |
| `release_date`, `knowledge_cutoff` | `YYYY`, `YYYY-MM`, or `YYYY-MM-DD`. Use the precision the document gives. A card's own date is not a release date; note it instead. |
| `context_window_tokens`, `max_output_tokens` | Integer tokens (`1000000`, not `"1M"`). Record the document's wording in `as_stated`. |
| `input_modalities`, `output_modalities` | List of `modalities` identifiers. |
| `reasoning_controls` | List of `reasoning_controls` identifiers. |
| `effort_levels` | List of lowercase level names exactly as the document uses them, such as `["low", "medium", "high", "xhigh", "max"]`. |
| `tool_use` | List of `tools` identifiers the document says the model uses or was evaluated with. |
| `open_weights` | Boolean. |
| `architecture` | An `architectures` identifier. |
| `parameters_total`, `parameters_active` | Integer parameter counts. |

### Capabilities, limitations, and other cited text

A *cited text item* is `{"text": "...", "pages": [12, 13]}` with 10–600 characters of text. Add `"document": "<supplement id>"` when it cites a supplement, `"section": "<heading>"` for a Markdown document, or `"source": "<url from sources>"` for owner documentation. One item cites one document or one source.

| Key | Items (with a document / without) | Content |
| --- | --- | --- |
| `capabilities` | 3–8 / 1–8 | What the model is and how it was built, how it differs from its predecessor, modalities and tools, and coding and agentic strengths and weaknesses. Prefer statements that change a choice. |
| `safety_findings` | 3–10 / 0–10 | Safety results not already covered by `agentic_risks` or the classification: dangerous-capability results, jailbreak and harmful-content results, welfare, and safeguards. |
| `limitations` | 3–8 / 2–8 | Known weaknesses, regressions, evaluation caveats, what the document says it did not test, and residual risks. |

### Evaluations

`evaluations` holds 0–30 rows: at least 8 for a document of 20 or more pages, at least 3 for a shorter one, and any number for a folder without a document. One row is one number the document reports for **this** model.

| Key | Type | Notes |
| --- | --- | --- |
| `benchmark_id` | vocabulary id | `benchmark` (the display name) is derived from it. |
| `variant` | string or `null` | Subset, split, or version detail that changes the number (`"Verified"`, `"Hard subset"`, `"WMDP-Bio"`). |
| `metric` | vocabulary id | From `metrics`, or `pass-at-k`, `mean-at-k`, `best-at-k`, `maj-at-k`, `cons-at-k` with an explicit k. |
| `value` | number | As the document prints it; do not round or convert. |
| `unit` | vocabulary id | `percent` for a 0–100 scale, `fraction` for 0–1, `score` for native points, and so on. |
| `higher_is_better` | boolean | `false` for compliance, attack-success, error, hallucination, dishonesty, sycophancy, and similar rates. |
| `effort` | string or `null` | The reasoning effort or thinking setting, lowercase, as the document names it. |
| `harness` | string or `null` | Agent scaffold or tool harness, such as `"mini-SWE-agent"` or `"Terminus 2"`. |
| `setting` | string or `null` | Other conditions that affect comparability: number of tasks, trials, tools, safeguards, or time limits. |
| `run_by` | `publisher`, `third-party`, or `not-stated` | Who ran it. |
| `comparators` | up to 6 | `{"model": "...", "value": 0, "setting": "..."}` for other models **the same chart or table reports**, in the same unit. Never import numbers from another document. Name a comparator by its `catalog.json` name when it is a catalog model (`"Claude Opus 5"`, not `"Opus 5"`), and otherwise as the document names it. Put its effort or other conditions in `setting`. |
| `headline` | boolean | Mark 3–6 rows that best show coding and agentic strength (benchmarks in the `coding`, `terminal`, `agentic`, `tool-use`, `computer-use`, `search`, or `ai-rnd` categories; `ai-rnd` covers publisher-run machine-learning engineering tasks such as MLE-Bench or kernel optimization). Safety measurements of agentic behavior, such as misbehavior rates, are never headline rows; record them as other results and in `agentic_risks`. When fewer eligible rows exist, mark them all. |
| `note` | string or `null` | Up to 240 characters for anything else a reader needs, such as non-comparability with an earlier version. |

Choose rows for decision value: the headline coding and agentic results first, then reasoning, long-context, multimodal, and the safety results a reader would compare across models. Two rows may not share the same benchmark, variant, metric, effort, harness, setting, and document.

### Safety classification

`safety_classification` records the publisher's headline determination:

- `framework`: `anthropic-rsp`, `openai-preparedness`, `google-fsf`, `xai-faif`, `other`, or `none-stated`. A named framework must belong to the model's publisher. Use `other` for any other named framework and give its name in `framework_name`.
- `overall`: up to 160 characters, in the document's terms, such as `"ASL-3 deployment standard"` or `"High capability in Biological and Chemical"`; `null` if none is stated.
- `summary`: 20–700 characters explaining the determination.
- `domains`: one entry per domain the determination covers: `domain` (vocabulary), `determination` (vocabulary), `level` (for example `"ASL-3"`, `"High"`, `"CCL not reached"`), `text`, and a citation.
- A citation for the whole classification.

Folders without a document use `none-stated` and no domains.

### Agentic-coding risks

`agentic_risks` lists each required topic exactly once: `reward-hacking`, `test-tampering`, `destructive-actions`, `sabotage`, `prompt-injection`, `honesty`, and `sycophancy`. Add the optional topics (`evaluation-awareness`, `sandbagging`, `cot-monitorability`, `self-preservation`, `malicious-use`, `over-refusal`) when the document reports them. Each entry is `{"topic", "status", "text", ...citation}`:

- `reported`: the document gives evidence for this model. Cite it and give the key number.
- `family-level`: the document reports it for the shared card without separating this model. Cite it and say so.
- `sibling-only`: the document reports it only for a sibling. Explain that it does not apply here.
- `not-reported`: the document does not cover it. Say what is missing.

### Choice guidance

- `choose_for` and `avoid_for`: 2–4 entries each (1–4 without a document), `{"use": "<use_cases id>", "rationale": "...", ...citation}`. A use case may not appear in both lists. Ground every rationale in the cited document; for example, avoid `untrusted-input` when prompt-injection results are weak or missing.
- `practical_implications`: 3–7 entries (2–7 without a document) of `{"text": "..."}`, the digest's own reasoning about using the model in the Copilot CLI or app: effort choice, review and verification practices, permissions, sandboxing, and prompt-injection exposure. They carry no citation, so they may state only Copilot facts that come from `catalog.json` (lifecycle, CLI and app availability, app reasoning efforts, Auto, long-context option) or official GitHub documentation. Do not invent Copilot features.

## Citations

- Pages are PDF page numbers from the extraction's page markers and must fall within the document's page count.
- A supplement item sets `"document": "<supplement id>"`. It renders as `(August update, p. 5)`.
- A Markdown document is cited by exact heading: `"section": "<heading>"`, rendered as `(§ <heading>)`.
- Owner documentation is cited with `"source": "<url>"`, which must also appear in `sources`.
- Every fact, evaluation, finding, limitation, risk (other than `not-reported` and `sibling-only`), and choice needs a citation. Wrong pages are errors.

## Scope

- **Attribute only this model's results.** On a family or shared card, never give a sibling's number as this model's. Where the document does not separate results by model, use `family-level` or say so in the text.
- Comparator models appear only inside `comparators` or text that names them.
- Set `coverage.card_type` from the definitions in `vocabulary.json`, and use `coverage.note` to say which pages apply.
- Known shared documents: GPT-5.4 and GPT-5.4 mini share the GPT-5.4 Thinking card (mini in its appendix). GPT-5.6 Luna, Sol, and Terra share the GPT-5.6 card, and its August update covers only Luna and Sol. GPT-6 Astra, Luna, and Sol share the GPT-6 Astra card (Sol and Luna in Appendix A). Claude Opus 4.8 and its fast mode share the Opus 4.8 card; fast mode runs the same weights with faster inference, as Anthropic's fast-mode documentation states. GPT-5 mini maps to `gpt-5-thinking-mini` in the GPT-5 card.

## Lifecycle

- `lifecycle` and `retired_on` come from the catalog. The renderer states a retired model's retirement date in the header and opens its guidance with a historical-use note; write the rest for comparison and lineage, and you may use `historical-comparison` in `choose_for`.
- For `limited` models, the catalog `note` appears in the header. Say who still has access only as GitHub documents it.

## Vocabulary

Identifiers are lowercase words joined by hyphens; versions keep their dots (`swe-bench-pro`, `terminal-bench-2.0`). Publisher-specific evaluations carry the publisher prefix (`anthropic-`, `openai-`, `google-`, `xai-`, `microsoft-`, `moonshot-`). Reuse an existing benchmark id whenever the document names the same benchmark, and use `variant` for subsets rather than a new id.

When no identifier fits, add one to `vocabulary.json` in the same change (keeping the existing structure), or pass a proposal file with only new entries to `digest_check.py --vocab-extra <file>` while drafting. The checker rejects a proposal that redefines an existing identifier. Identifiers are stable once published; display names and descriptions may be refined.

## `digest.md` layout

The renderer produces a title, a header block quote naming the document (with the full-text clause the rights rules require), a Copilot status line from the catalog, and exactly these seven `##` headings, in this order:

1. **At a glance:** the summary, the *Choose it for* and *Watch out for* lines, and the points.
2. **Capabilities:** a key-facts table, then capability notes.
3. **Evaluations:** a comparability caveat, the headline table, and other reported results.
4. **Safety findings:** the classification, the per-domain table, agentic-coding risks, and other findings.
5. **Limitations and caveats.**
6. **Practical implications for Copilot users:** *Choose it for*, *Avoid it for*, and guidance.
7. **Document coverage.**

## Originality, accuracy, and safety

- **Paraphrase, don't copy.** The checker rejects any run of 12 or more consecutive words that also appears in the source. Text inside double quotes is exempt; keep such quotations short, rare, and under 15 words.
- **Facts may be reproduced.** Benchmark names, model names, and numbers are facts.
- **Stick to the public document.** If the document does not report something, use `null` or `not-reported` and say so; do not fill the gap from elsewhere. Copilot facts come only from `catalog.json` or official GitHub documentation.
- **Keep it public-safe.** No customer names or information, internal model identifiers or codenames, model-picker entries GitHub has not made public, or pricing, billing, premium-request, or multiplier language.
- **Style:** neutral, precise American English with no marketing tone. Lead with what matters for model choice.

## Check

```sh
python3 digest_check.py --write <slug>   # normalize digest.json, render digest.md, then validate
python3 digest_check.py <slug>           # validate only; uses the folder's local extraction for the copy check
python3 generate.py --check              # every folder, the vocabulary, generated files, and rights rules
```
